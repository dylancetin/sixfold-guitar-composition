# U02: bounded export proof

This is a self-contained experiment, **not the application or its shared schema**.
It does not import any copyrighted song. Only this package and
`docs/evidence/export-proof.md` belong to this unit.

## Run

Tested with Node **24.12.0**, npm **11.6.2**, Linux x64. No browser, preview server,
audio device, globally installed PDF tools, or root package is required.

```sh
cd tools/export-proof
npm ci --no-audit --no-fund
npm test
npm run proof
npm run verify
```

`proof` runs negative-control tests **before** invoking the exporter, writes real
MIDI and PDF bytes, exports deliberately corrupted files, then starts the
independent verifier in another Node process. `verify` only reopens existing
artifacts; it does not invoke alphaTab. A custom local output directory works:

```sh
node run.mjs /tmp/opencode/my-u02-run
node verify-artifacts.mjs /tmp/opencode/my-u02-run
```

Exit code 0 means automated fixture predicates passed. It does **not** mean a
human inspected the generated PNGs, listened to MIDI, or approved playability.

Generated files are ignored under `artifacts/`. Do not commit generated artifacts,
dependencies, or local reports. `unit-log.tsv` in this package is the historical
handoff log for the parent; each run also emits an artifact-local `unit-log.tsv`.
Neither script edits `docs/decisions.tsv`.

## Literal, original fixture and independent expected answer

The newly authored **Copper Steps** fixture and its event oracle are dedicated
under **CC0-1.0**. They are not transcriptions or adaptations of the requested song.
There are 16 distinct source bars and **24 literal performance-bar rows**, in 4/4:

`1–8, 5–8, 9–16, 13–16`.

This sequence is already unfolded. The adapter does not expand or independently
interpret repeats. Engraved `Oxx/Sxx/Px` labels mean occurrence/source/pass.
Effective entry BPM is explicit in every row, including restoration from 120 to
96 at O09 and 72 to 104 at O21. Ties continue across O04→O05, O06→O07,
O10→O11, and O16→O17. At the two backward source jumps, entry notes are new
attacks, not continuations of a tie outside that pass.

- `fixtures/engraving.tsv`: all three independent voices, rests, standard-guitar
  placements, notation durations and tie destinations, literally written out.
  Tokens: `4:1/2` = quarter note, conventional high-E string 1, base fret 2;
  `4t`/`8t` = 3:2 quarter/eighth triplet; `2.` = dotted half;
  `-` = rest; comma-separated placements = chord; `^` = tie continuation.
- `fixtures/oracle.tsv`: **separately authored literal sounding events** for all
  24 occurrences: `MIDI_pitch@quarter_offset:quarter_duration`. Ties are already
  merged and rests appear as intentional gaps. It has no string/fret tokens or
  notation interpretation. Expected values are never generated by the adapter.
- `fixtures/expected.json`: literal form/pass/tempo oracle, revision, PPQ and
  guitar conventions. This is not an approved application contract.

The fixture has 156 notation note segments, four tie destinations and **152
attacks**: melody 76, bass 36, harmony 40. It ends at 96 quarters / tick 92,160.
PPQ 960 represents both kinds of triplet exactly (640/320 ticks). The ten tempo
events use `floor(60,000,000/BPM)` microseconds/quarter, the observed alphaTab
conversion; only this declared tempo conversion is rounded.

## Capo and written guitar octave

The same sounding fixture is exported at capo 0 and capo 2. All base frets are
at least 2, so the capo-2 projection can subtract two from every relative fret
without changing strings or pitches:

```text
sounding MIDI = open tuning + capo + relative fret
physical neck fret = capo + relative fret
written MIDI = sounding MIDI + 12
```

Example: high E / capo 0 / relative fret 2 and high E / capo 2 / relative fret 0
both sound MIDI 66 and are written as F#5 (MIDI 78). The complete MIDI files are
byte-identical. Native alphaTab `Note.string` numbers from the **low** string,
unlike this fixture's conventional high-string-first notation. Its tuning array
is high-to-low. The adapter converts this explicitly.

Set native `staff.capo=2`, leave `transpositionPitch=0`, and use
`displayTranspositionPitch=-12` for guitar notation. Native capo already changes
pitch; additionally setting native transposition to -2 produces an incorrect
extra +2. The script generates that actual bad MIDI and requires rejection.
`placements.json` records both fret conventions and actual/written pitch for
every notation segment. PDF.js also checks the first F#5 notehead's actual
baseline against the top treble-staff line, independently of native getters.

## PDF route and checks

alphaTab 1.8.4 renders SVG. The adapter waits for `postRenderFinished`, checks
finished bounds and exact bar coverage, and verifies each musical partial is
exactly one complete system, using both its bar range and visible bounds.
It never assumes arbitrary partials are systems. Over-height systems reject.
All system units retain a constant page-wide scale and their original x offset.
Header/footer partials are treated separately.

PDFKit 0.20.2 + SVG-to-PDFKit 0.1.8 produce real local `.pdf` bytes with explicitly
embedded Bravura. SVG `class="at"` is materialized as font-family/size attributes.
**SVG-to-PDFKit viewport width is not a scale override:** explicit SVG px sizes
otherwise retain implicit 72/96 scaling. The adapter instead owns the PDF
transform and sets `assumePt:true`; independent glyph geometry checks its scale.

PDF.js 6.4.299 parses and rasterizes **every page**. Checks include native engraved
bar/source/pass text, revision/capo labels, final bar, embedded Bravura data,
treble/TAB glyphs, vector-detected five/six-line groups for each complete system,
and actual raster sampling of every staff/TAB line. The latter detects a real
clip even when PDF text extraction still returns hidden content. Every positive
page is saved at 1.5× scale for review.

The literal MIDI checker uses `midi-file` 1.2.4 and a separate `@tonejs/midi`
2.0.28 reparse. It checks exact event union, balanced on/off, acoustic program 24,
all tempos and the last endpoint. No native MIDI readback is used.

## Artifact index

- `generation.json`: input digests, pinned versions, revision and capo evidence.
- `verification.json`: parsed results, all-page text/fonts/geometry, negative
  control rejections, and SHA-256 hashes of PDFs/MIDIs/PNGs/SVGs.
- `capo-{0,2}/fixture.mid`, `A4.pdf`, `LETTER.pdf`.
- `capo-{0,2}/{A4,LETTER}-raster/page-NN.png`: every page.
- `capo-{0,2}/render-layout.json`, `*-pagination.json`, `partial-NN.svg`,
  `placements.json`: native geometry and adapter placements, not independent
  expected answers.
- `negative-controls.tap`: 18 predicate tests, including omitted notes/tuplets,
  octave, capo, ties, form, harmony, revision, font and clipping mutations.
- `negative-*.mid` and `negative-*/A4.pdf`: nine actual corrupted-file controls.
- `license-inventory.json`, `Bravura-OFL.txt`, `alphaTab-MPL-2.0.txt`.

## Licenses and limits

alphaTab is MPL-2.0, unchanged, installed through its pinned npm package; covered
library files/notices and source-availability obligations must be retained when
distributed. Bravura is OFL-1.1; its notice is copied beside generated exports.
PDFKit, SVG-to-PDFKit, midi-file, Tone MIDI and napi canvas declare MIT; PDF.js
declares Apache-2.0. The rerunnable inventory records installed notice paths and
hashes. This direct-dependency inventory is **not a legal audit of every native
transitive component**. No importer/converter code was copied. Bundled Sonivox
SoundFonts are not loaded, embedded, or redistributed by this proof.

This proves this fixture on the pinned route, not arbitrary notation. It has no
interactive controls, browser/audio readiness proof, role mute projection,
revision approval system, requested-song export, fingering solver, difficulty
calibration, audible second-player check, or human playability review. Letter
deliberately keeps the final system intact on a sparse fifth page. alphaTab's
native capo caption appears three times (once per voice): cosmetic, unresolved.
